# os/sync.h



## 内容与边界

SpinLock、Mutex 都是直接有状态的锁对象，不为嵌套而增加一个无用途的 Sync 外壳。各自的作用域守卫分别收进 SpinLock::Guard、Mutex::Guard，构造加锁、析构解锁，禁止复制。

AddressWait 绑定一个借用的等待字，提供 wait、wakeOne、wakeAll。Mutex 使用原子快速路径，竞争时用 WaitAddress/WakeAddress；等待时重新检查条件并使用正确内存序。SpinLock 只用于短临界区，不能跨文件系统或服务等待持锁。

## 类与函数

### SpinLock

这个类表示适用于短临界区的自旋锁。

#### 操作

```cpp
void lock();
```

用途：取得锁；Mutex 竞争时休眠，SpinLock 只适合短时间竞争。

参数：无。

结果：不返回数值；带有 noreturn 的当前上下文退出函数成功后不返回调用位置。

```cpp
bool tryLock();
```

用途：只尝试一次取得锁，不等待其他线程释放。

参数：无。

结果：返回 true 或 false，具体含义见用途。

```cpp
void unlock();
```

用途：释放当前线程持有的锁，让其他等待者继续。

参数：无。

结果：不返回数值；带有 noreturn 的当前上下文退出函数成功后不返回调用位置。

### SpinLock::Guard

这个类表示一个作用域内的自旋锁持有关系。

#### 构造与析构

```cpp
explicit Guard(SpinLock& lock);
```

用途：构造时取得参数中的锁；构造完成后当前作用域持有该锁。

参数：

- `SpinLock& lock`：作用域内需要加锁的自旋锁对象。

结果：构造完成后已取得指定锁，没有错误码返回。

```cpp
~Guard();
```

用途：离开作用域时释放构造时取得的锁。

参数：无。

结果：析构函数没有返回值，不抛出异常。需要确认操作结果时使用明确返回状态的业务函数。

### AddressWait

这个类表示一个需要比较、等待和唤醒的用户地址。

#### 构造与析构

```cpp
explicit AddressWait(volatile uint32_t& address);
```

用途：建立一个需要比较、等待和唤醒的用户地址；只保存借用数据或设置时，不接管调用者缓冲区。

参数：

- `volatile uint32_t& address`：希望使用的虚拟地址或待检查的内存地址；空值的解释见构造说明。

结果：构造完成后可使用本类查询或参数设置函数；不返回数值。

#### 操作

```cpp
int wait(uint32_t expected);
```

用途：等待线程退出、输入事件、文件完成或地址值变化；具体等待对象由当前类决定。

参数：

- `uint32_t expected`：只有地址当前值仍等于此值时才进入等待，避免错过已经发生的修改。

结果：0 表示成功，负 ErrorCode 表示失败；输出参数仅按本函数说明在成功或部分完成时有效。

```cpp
int wakeOne();
```

用途：唤醒等待同一地址的一个线程。

参数：无。

结果：返回实际唤醒的线程数量，负值表示地址或参数错误。

```cpp
int wakeAll();
```

用途：唤醒等待同一地址的全部线程。

参数：无。

结果：返回实际唤醒的线程数量，负值表示地址或参数错误。
