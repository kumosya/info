# 服务故障恢复契约

本文记录正在实施的恢复协议，不代表所有服务均已支持状态恢复。阶段状态见 `../prompt/v0.1-login-dma-service-recovery-progress.md`。

## 身份和生命周期

稳定服务身份由固定角色及受管启动关系决定，不允许普通进程按名称创建恢复域。实例身份为 Task ID、地址空间 generation 和恢复 epoch。业务对象使用稳定 ID，不能以局部句柄号或进程指针充当永久身份。

恢复顺序为失效旧实例、接管记录/能力、恢复事务、对账验证、绑定服务、发布业务 ready。旧实例失效后不能提交新状态，客户端不得因为发现新端点就假定原对象已恢复。

## 状态和能力

当前已实现受管角色隔离、epoch/序号校验、预留后提交的不可变检查点、有界增量日志、页/共享对象引用托管和受保护端点接管。MM 使用检查点恢复 VMA 与事务；users 通过内核认证标记重建会话/runtime 引用；pipe 按字节流事务恢复。MM/users/pipe 的受控 restart 已接入并通过各自故障测试，组合及最终发行验证见执行记录。

| 服务 | 当前业务恢复保证 | 仍需完成 |
| --- | --- | --- |
| init / 注册表 | 监护与失效发现 | 根监督者自身恢复、注册/控制端点与存活子服务接管 |
| task | 派生服务监护与受控终止 | 自身状态及现存 pipe/msgq 子实例接管 |
| pipe | 旧流/能力、消费结果、EOF、非阻塞、阻塞客户端续接；支持 restart | 继续组合和容量故障验收 |
| msgq | 尚无业务状态恢复 | 消息、优先级、打开对象、消费结果、通知交错 |
| device / input | 设备资源回收与输入背压 | 自身及 input 状态、存活驱动接管 |
| pci | 可重新发现设备 | 与新设备实例的完整恢复协调及验收 |
| storage | 已支持驱动故障后的安全 reset/隔离/回收 | 正常排空/flush、在途结果、未知写入和上层协调 |
| fs | MM 租约跨 MM 实例；ext3/ext4 保留 unlink 后 inode | FS 自身打开对象/offset/挂载/事务恢复，FAT32 寿命 |
| mm | 旧 VMA/页/backing/COW 及请求结果；支持 restart | 并发 fork、FS 同时故障、损坏/低内存组合边界 |
| users | 从内核认证身份重建引用并保留 runtime 文件；支持 restart | 继续与 FS 故障组合验收 |
| tty | 尚无旧 PTY 状态恢复 | 旧能力、队列、行规程、前台组与通知 |
| console | 文本会话退出后的重新登录可用 | 服务自身重启后的旧终端状态 |
| guiw | 点击和交互回归另行执行 | 服务自身重启后的旧窗口、焦点及共享 surface |

除已明确开放的 MM/users/pipe，不能把自动拉起新进程或重新注册端点解释为旧业务状态已经恢复。服务状态的 epoch、恢复阶段和隔离统计展示仍在后续阶段。

| 资源 | 权威位置 | 故障后要求 |
| --- | --- | --- |
| Task 身份/地址空间 generation | task.kernel | 用来过滤退出/exec 的旧业务记录 |
| VMA/backing/COW 策略 | Ring3 MM | 提交数据独立于 MM 进程存活，重启时由 MM 解释并恢复 |
| PTE/页对象/共享对象引用 | 现有内核内存机制 | 对象被恢复记录引用期间不能提前释放 |
| 文件映射对象/打开文件位置 | Ring3 FS | 保留 inode/打开对象身份，不按旧路径重新打开替代文件 |
| pipe/msgq 内容与消费位置 | 各自 Ring3 服务 | 已确认写入不丢，消费结果去重，旧能力可接管 |
| DMA 页/设备归属 | device.kernel 资源域 | 设备确认停止之前保持固定；失败隔离 |
| IRQ/MMIO | 内核设备机制 | 与 owner、设备域及代际关联，退出后撤销旧访问 |

内核只托管不可变提交数据、能力引用、代际和接管权限，不解释 Ring3 服务的业务布局。共享 staging 区不等于已提交状态，不能在回复成功后才将状态写入检查点。

正常线程退出不在任务锁内关闭全部句柄；任务回收器先取消旧端点归属，再释放句柄、映射及地址空间。恢复域 Acquire 在上一实例已经退出但资源回收未完成时返回 WouldBlock，新实例在 20 秒内有界等待，避免提前接管与旧清理交错。普通端点最后一个接收者关闭仍会销毁端点；托管端点的特殊接管语义仅限已授权恢复域。恢复测试交替覆盖正常退出和受控强退共 32 轮。

## 有界增量日志

RecoveryPrepare 的模式 0 为完整检查点，模式 1 为增量记录预留。RecoveryAppend 只发布模式 1 已预留的私有副本，不接受陈旧序号，也不能把日志预留当作完整替换。RecoveryReadLog 返回只读记录能力、有效字节数和连续提交序号；Acquire 同时返回完整检查点序号与后续记录数量。Ring3 先验证检查点和全部记录，再恢复最终引用，不在重放中间状态时打开已被后续事务淘汰的对象。

每条记录最多 64 KiB，每角色最多 128 条，日志按实际分配的物理页累计不超过 4 MiB；完整检查点另限 4 MiB。空间不足在业务修改前返回 WouldBlock，服务先压缩为完整检查点，再预留新记录。完整提交原子发布新快照并清除旧日志；读者已持有的旧只读页继续有效。未提交的预留在实例退出后丢弃。所有记录布局、版本和校验和由 Ring3 负责，内核不解释管道字节或队列消息。

RecoveryGeneration 只向已持有当前 epoch 的受管实例返回目标 Task 的地址空间代次，用于过滤 exec 后的旧请求结果；它不授予跨进程内存统计、映射或写入权限。普通程序、旧 epoch 和旧实例均不能调用。

## 事务

每个有副作用或消耗数据的请求有稳定 ID。事务先预留日志/结果和对象引用，再执行可恢复步骤，提交最终状态及结果后回复。跨 PTE、FS、设备的操作分别记录阶段，并提供幂等补完或回滚动作。

reply token 属于一次 IPC 调用，不可恢复为新实例的回复权限。客户端重新发现服务后，按原请求 ID 查询/续接，不直接再次执行未知结果的操作。结果记录应有确认与有界回收协议。

设备写入与 flush 的完成不同。不能判断物理写入结果时明确返回不确定状态，受影响卷进入恢复或只读状态；不得无序重放旧写入。

## 设备资源域已实现的保证

现代 VirtIO block 通过受管 claim 取得资源域，DMA 分配引用该域，MMIO 范围使用开启 DMA 前缓存的 BAR 信息。物理页归域持有，服务映射是外部引用。

退出先停止服务线程并使域失效。独立 worker 撤销 MMIO、关闭 bus master、写设备 reset 并确认状态为 0；只有确认停止、所有对象句柄释放且旧地址空间销毁后，才释放 DMA 页。失败进入隔离并保留页，不阻塞全局 TaskReclaimer。

正常关闭也会先撤销映射并保留域资源到设备停止。域拥有者不能 fork 硬件映射；exec 以地址空间 generation 区分旧映射，避免清理旧对象时误撤销新程序映射。

支持范围是当前现代 VirtIO block 的可信 reset 机制。新增驱动必须明确其停止证明，不能用 IRQ 屏蔽或随意注册的用户回调代替 DMA 停止。

## 必须拒绝的降级

- 重启后创建空对象却复用旧 ID。
- 清空 VMA 或杀死所有客户端来伪装恢复成功。
- 仅保存元数据而不保留其唯一页/文件/能力引用。
- 日志满时先执行再丢弃记录。
- 托管句柄被计作业务读写端，导致 EOF 或 unlink 后回收永久失效。
- 恢复失败时静默扩大权限或把未知外部结果报告成功。

恢复保证针对同一内核启动内的服务退出；整机掉电、内核损坏及介质故障需要各自的持久化与修复协议。
