# 服务、任务与运行时完善：执行记录

总任务依据：[总执行 Prompt](v0.1-service-task-runtime-master-prompt.md)。本文件持续记录实际结果，未完成项不能视为已经验收。

## 基线

- 已核对服务生成器、init、任务接口、FS 虚拟目录、ps/killall 与 GUI 终端实现。
- `/sys` 明确存在目录打开缺陷：stat/readdir 已处理虚拟目录，但 FS open 拒绝非普通 SystemFile，导致 libc opendir 失败。
- 旧系统镜像固定位置 3000 次点击与键盘输入通过，日志 `build/runtime-baseline-input.log`，串口与截图位于 `/var/tmp/osinfo-runtime-baseline/`。此结果没有覆盖用户实际的全部点击操作，不能据此声称崩溃已经修复。

## 正在实施

- 首轮 C++ 标准头、os::Task 类和方法名迁移覆盖 84 个源码/模板文件，清单为 build/runtime-api-migration-files.txt；保留 C 源码和标准包装头内部对 C 声明的包含。
- 已删除公共 TaskListEntry/listTask/enumerateTask，迁移 ps/pkill/killall/who 的枚举到 procfs 读取器；users 的 Who 查询改为按 PID 查询。
- 新增 procfs 节点和单调 PID 枚举游标，进程文件在打开时快照，补充任务启动时间、CPU 计时、会话、进程组、终端、参数元数据。正在进行运行验证。
- 修正 /sys 目录 open；补充 procfs 只读打开和快照读取。
- `make sdk/check` 已完成源码审计与 SDK 导出，日志 build/runtime-build.log；基础工具、GUI、inpkg 正在使用新 SDK 重建，尚未做新系统集成启动。

- task 实际启动并持有 pipe/msgq 的监护句柄；device 实际启动并监护 pci/storage。已在新镜像串口确认该顺序。
- users/tty/console/guiw 从 `/etc/services` 配置的磁盘 ELF 加载，已成功启动；不再进入 GRUB 服务模块列表。首次失败暴露共享运行库来源地址空间混用，现已分别记录并修复。

- os::Task API、TaskInfo、procfs 与目录协议同步改动；目录返回真实 inode 和 nextOffset，libc 移除 /proc 游标特判。/sys 和 /proc 已纳入只读虚拟后端，users 不再 chmod /proc。
- 独立 `osinfo-base-tools/systemctl` 为第五个项目，五个 inpk 汇总为 ZIP。管理协议区分 desired 与 enabled；启停由实际 owner 执行，普通正 PID/组信号和 terminate 均保护服务标记。
- 完成受影响项目首轮 SDK/包重建；当前最后一轮镜像、资源与验证尚未全部结束，不能据此宣布交付完成。

## 输入冻结的确定性证据

用户补充：在桌面不同窗口和控件间切换，点几次按钮后死机，且不能再切 TTY。

定位到 device 内 InputService::notifySubscribers 使用阻塞发送。IPC 通知队列满后，IRQ 输入线程阻塞，无法继续获取鼠标或键盘，符合两个输入同时失效的表现。

- 测试 `tests/input-backpressure.cc` 创建活动订阅者并故意填满其通知端点；QEMU 随后输入鼠标及 Ctrl+Shift+F1/F7。
- 修复前：`build/runtime-input-pressure-before.log`，证据目录 `/var/tmp/osinfo-input-pressure.vae5I0/`；报 `keyboard/TTY switching stalled after mouse input`，串口停在订阅队列满与会话启动日志，未出现切换 tty1。
- 修复后：通知 deadline=0，暂时背压保留订阅并在请求循环最多 10 ms 后重试；永久错误才退订。相同场景通过 16 次点击和键盘/TTY 切换，日志 `build/runtime-input-pressure-after.log`，证据目录 `/var/tmp/osinfo-input-pressure.owo7gA/`。
- 这证明慢订阅者不再冻结全输入；跨窗口长期点击、服务实例稳定和资源增长的扩大验证仍在执行，不把单场景通过当作全部桌面验收。

## 运行时测试正在收敛

`tests/service-runtime.sh` 在隔离系统镜像内运行 C++ 验收程序，不引入独立冒烟配置文件。已实际通过 /sys、尾斜线、嵌套目录、/proc/self、inode、ps 指定选项及 systemctl 列表。服务父子/保护和 start/restart 已通过；enable 暴露 File::fsync 原实现返回 ENOSYS，已补 FS Sync RPC 与实际文件系统同步，正在复验。

PTY 改为可关闭、可 join 和可复用槽位；shell 异常后 GUI 终端回收旧 PTY 并启动 recovery 登录程序，文本会话重置输入/光标/历史/前台状态。新增 20 轮 PTY 回收与六 TTY 多轮恢复验收，尚需以最终运行结果更新。

另修复启动探针竞争：原线程入队后再设 CPU 亲和性，可能在线程运行完后失败；现在创建线程入队前设置亲和性。该问题与输入冻结分开记录。

服务主文档已迁入逐服务目录，派生服务与 Ring0 机制按 task/device/mm 归属；历史平铺文件只保留导航以保持架构文件链接。`docs/architecture.md` 未修改。最终源码、链接、SDK/包、InfoIDE 资源和运行验收仍需完成。

线程记录回收采用 join 消费和旧栈退出两个条件汇合：CPU 切离后才能回收，创建入口先缓存 TID 再入队。该变更没有增加 syscall，也未向 memory.kernel 重新加入映射 RPC。

服务构建配置现在为 17 列，源码来源、boot/file/resident 加载来源与 owner 分开表达；运行时服务和会话入口分别只有 `/etc/services`、`/etc/sessions`，console 为 `/etc/console`。已有 console.conf 的内容在部署时迁移到尚不存在的 console，保留原文件作为历史副本。

输出位置为 OS 的 `build/export/osinfo.img`、`build/export/osinfo.iso`、`build/sdk/`，基础工具的 `../osinfo-base-tools/build/osinfo-base-tools.zip`，InfoIDE 自己的 `../infoide/build/infoide-linux.tar.gz`。InfoIDE 安装、卸载和发行包构建仍归 InfoIDE 项目；OS 未加入专用安装目标。

明确限制：基础引导服务暂不允许 systemctl 停止/重启/禁用；文件服务 owner 当前仅支持 init；proc stat 为已说明的基础格式，非完整 Linux ABI；端点重建不恢复 VMA、打开文件、DMA、管道或队列内容；固定容量仍按各服务文档限制执行。压力验证不代表无限负载保证。

自动审批拒绝删除已停用的 `config/applications.conf` 与 `build/generated/sessions.inc`，仅返回“策略阻止”。两个旧本地文件保留，新生成/运行链路均不使用它们；没有绕过该拒绝进行清理。
