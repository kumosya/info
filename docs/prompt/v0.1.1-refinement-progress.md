## 源码与服务归位

| 对象 | 当前源码 |
| --- | --- |
| Ring3 MM | `src/mm/` |
| Ring3 task / pipe / msgq | `src/task/main.cc`、`src/task/pipe/`、`src/task/msgq/`，分别构建 |
| Ring3 device / PCI / storage | `src/device/main.cc`、`src/device/pci/`、`src/device/storage/` |

`user/` 只承载程序。服务源码选择按目标明确分组，task/device 不会递归纳入子服务的 main。头文件审计、内存测试路径及 SDK 公共头文件随迁移更新。

## syscall 与服务能力对照

| 能力 | 迁移后入口 | 授权与实现 |
| --- | --- | --- |
| 匿名映射 | syscall 8 / MapMemory，kind=0 | 当前进程或固定 MM 角色及 Memory 能力；复用 MappingOperations |
| 页对象映射 | syscall 8，kind=0x100 | 页对象类型、句柄读写权限及 W^X；复用 PageMappings |
| 共享对象映射 | syscall 8，kind=0x200 | 共享句柄权限；跨任务通过受检句柄复制，完成后关闭临时句柄 |
| 解除映射 | syscall 9 / UnmapMemory | target=0 为自身，其他目标检查固定 MM 角色与能力 |
| 权限与 COW 标记 | syscall 10 / ProtectMemory | 普通保护沿用权限上限；COW=4 只供固定 MM 身份 |
| 页对象分配/信息、共享对象管理 | memory.kernel | 保留真实对象机制，不提供映射 RPC |
| usage、回收、pager 绑定与状态查询 | memory.kernel | 保留独立机制与授权 |
| fork/exec、退出、线程创建、同步 | 既有 syscall | task.kernel 不增加同类重复入口 |
| 磁盘读取/加载与任务管理策略 | Ring3 task | 底层任务对象操作由独立 task.kernel 实现 |

移除了 Map、MapPages、MapSharedTarget、UnmapTarget、ProtectTarget 的服务分发与枚举引用；旧编号留空，不重用。Memory 的相应客户端方法直接调用 syscall。有效 syscall 仍为 19 个，编号未变；SDK、程序、服务需配套重建。

公共 os/ 头文件不再读取 CS；通用 syscall 包装移除级别判断与 Ring0 coreCall 旁路。CS=3 检查保留在私有服务入口。PCI 原始端口访问位于内核 PCI 目录，PS/2 位于内核设备实现，普通文件 I/O 接口不受此限制。

## 配置与系统组件

- 系统版本唯一配置源：`script/lib/version.1`，当前 `0.1.1`；镜像位置 `/lib/version.1`。
- hostname 复用 `script/etc/hostname`，镜像位置 `/etc/hostname`。
- FS 选定根卷后通过底层 FileSystem 直接读取，启动时缓存，修改后重启生效。缺失或非法内容明确使 FS 初始化失败，不静默回退。版本及 hostname 节点不依赖实时统计成功。
- sysinfo 和 shell 的 hostname 展示使用 `/sys/kernel/hostname`，sysinfo 不采信可伪造的 HOSTNAME 环境变量。
- ld-osinfo 从 `build/lib/ld-osinfo-x86-64.so` 直接部署到同名 `/lib/` 路径，移除普通包配置与产物链路。SDK 仍提供配套副本。
- 离线包安装器、CLI 及目标 inpkg 拒绝包覆盖解释器与版本文件；镜像更新移除旧 ld-osinfo 包状态记录。

## 独立项目

`D:/osinfo/osinfo-base-tools` 包含 sysinfo、mount/umount、mkfs 和 27 个 coreutils 命令，共 31 个。以一个 osinfo-base-tools 包发布，保留命令位置；共享头文件随源码迁移，独立项目只使用 SDK。OS 外部包清单现在要求 guiw、inpkg、osinfo-base-tools，缺少时明确失败。

`D:/osinfo/infoide` 已替换为 Linux C++ CLI，删除旧 Python 浏览器 IDE、web 资源及其旧测试。支持 create/build/pkg、编译器/SDK 选择、C/C++/汇编、包含目录、库目录、链接库、目标共享库、runpath 和安装映射；通过参数数组执行编译器与 tar/gzip，不调用 Python 业务后端。pkg 总是重建，产物通过临时文件发布，构建开始时使旧同名包失效。

guiw/inpkg 的 Makefile 也使用新 CLI，已配套重建和导入。OS 原有镜像、包导入脚本与 SDK 旧项目兼容脚本继续存在，不作无关重写。

Linux 使用步骤：

```sh
make -C ../infoide
make sdk
make -C ../osinfo-base-tools package
make -C ../guiw
make -C ../inpkg
python3 script/import-package.py ../osinfo-base-tools/build/packages/osinfo-base-tools.inpk
python3 script/import-package.py ../guiw/build/packages/guiw.inpk
python3 script/import-package.py ../inpkg/build/packages/inpkg.inpk
make all
```

新项目使用 `osinfo create hello`、`osinfo build --sdk /path/to/sdk`、`osinfo pkg --sdk /path/to/sdk`。配置与参数优先级见 [CLI 与 SDK](../app/infoide.md) 及独立项目 README。

## 文档与实现原则

已更新 README、设备与 PCI/storage 服务、task/pipe/msgq/init/fs、内存/syscall/IPC、动态链接器、OS 库接口、InfoIDE、包管理及独立项目说明。设备文档中失效的历史 syscall 编号已替换成真实驻留端点操作。架构文件保持原样；既有架构文档中的历史目录不会由本轮偷偷改写，以本实施记录和当前服务文档核对位置。

KISS：版本采用文本文件，不新增无必要共享库。DRY：映射只有 syscall 入口，复用现有内核机制。单一职责：各服务独立目录与实现，聚合文件仅组装端点；CLI 分离配置读取、子进程、文件和项目流程。YAGNI：不扩展 GUI、Windows、调度算法、swap 或无需求兼容框架。

## 保留边界

- CLI 首期全量构建，没有增量缓存或 GUI；归档使用 Linux tar/gzip。
- FS 的格式化请求原本不实现写盘，mkfs 继续明确失败；本轮不扩展格式化器。测试验证其失败语义，不能宣称已完成真实介质格式化。
- 原有 MAP_FIXED、文件/匿名 MAP_SHARED、swap、MM 重启后 VMA 恢复等限制不因目录迁移而扩展。
- 本轮不执行 Git 提交、推送或分支操作，不修改系统环境变量或全局安装工具。
